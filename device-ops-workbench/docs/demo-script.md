# 演示脚本（3–5 分钟）

> 目标：让面试官/答辩老师看到「知识—报修—设备—现场」是一条线，而不是四个孤立页面。

## 0. 打开（10 秒）

启动 `python app.py`，浏览器打开 `http://127.0.0.1:8100/`。

开场：

> 这是一个设备运维工作台：一个进程里同时有知识问答、报修工单、现场排障和统一模型配置。
> 不填 API Key 也能完整演示：问答返回知识库原文，报修走规则分诊。

## 1. 知识问答（60 秒）

1. 在对话页输入：`光猫 LOS 红灯怎么办`
2. 指出回答下方的来源卡片：文档、章节、相似度，可展开原文。
3. 追问：`那重启之后还是红灯呢`，说明多轮指代会拼接上一轮问题检索。
4. 点左侧「检索评估」：Recall@1/3/5、Hit@5、MRR 和未命中案例。

话术：

> 回答不是模型自由发挥：提示词只允许依据检索资料，强制 JSON，输出不合规就降级为原文。
> 34 题测试集把检索质量量化成指标，失败案例也留着。

## 2. 报修 + AI 分诊（90 秒）

1. 点左侧「报修工单」→ 学生端。
2. 输入：`实验楼305交换机端口灯不亮，整层上不了网`，地点 `实验楼305`。
3. 提交后指出：工单号、类别「网络」、优先级、3 条自查步骤、分诊方式（AI/规则）。
4. 如果配置了 Key：展开管理端详情，指出「分诊依据（知识库）」的来源章节。
5. 在描述框输入 `投影仪开不了机`，停顿 0.5 秒，出现「历史相似工单（已解决）」。

话术：

> 分诊先用 RAG 检索知识库，再让模型输出结构化结果；模型超时/无 Key/JSON 不合规都会退回规则，
> 报修永远不会因为 AI 挂掉而无法提交。相似工单只取已关闭记录，且不返回报修人信息。

## 2.5 SLA 与经验沉淀（60 秒）

1. 管理端顶部看「已超时」统计卡；列表里超时工单有红色「已超时」标记。
2. 打开一张已完成工单 → 底部「沉淀为经验」。
3. 指出草稿已自动脱敏（手机号、姓名、房间号），补一句「结论」，点「保存并重建索引」。
4. 回到问答输入工单里的故障词，来源里出现 `experience/工单_BX....md`。

话术：

> 这一步把一次维修变成可复用的知识，但不会自动入库：必须管理员审核，未完成工单不允许沉淀。

## 3. 设备二维码（60 秒）

1. 管理端 → 设备资产 → 新增 `NET-AP-001 / 3号楼502 无线AP / 网络设备`。
2. 点「二维码」，新窗口打开 PNG；用手机扫码（或直接打开 `/a/NET-AP-001`）。
3. 展示设备档案、保修期、历史工单；点「报修这台设备」，学生端自动带设备与位置。

话术：

> 一物一码，扫码就能看到这台设备修过几次、保修到什么时候；报修自动关联设备，
> 同类故障重复出现时能直接看出来。

## 4. 现场排障（30 秒）

1. 点左侧「现场排障」→ 包装页内嵌原单文件助手。
2. 搜 `光猫` 或点一个场景，展示「现象 → 判断 → 原因 → 步骤 → 上报」。
3. 说明手机可离线打开原 HTML，不依赖服务。

## 5. 统一配置 + 全局搜索（40 秒）

1. 按 `Ctrl+K`，输入 `设备`，展示知识/工单/设备/操作四类结果。
2. 点「模型设置」：供应商、Base URL、API 格式、模型、上下文、最大输出、思考等级、参数映射。
3. 指出对话框旁可切换模型与思考深度；问答和报修共用这一套配置。

## 6. 收尾（20 秒）

> 三个原项目仍然独立可运行；统一版只是把数据流接起来。
> 测试 91 项 + 管理员口令 10 项，覆盖入口、问答、分诊、规则兜底、SLA、经验沉淀、资产二维码、演示模式和 Key 脱敏。

## 无 Key 时的演示路径

- 问答：检索模式，返回完整章节原文 + 来源卡片。
- 报修：规则分诊（关键词 + kb_snippet 自查步骤）。
- 管理端：AI 状态显示「规则模式」，其它功能不受影响。
