> 用途：毕业设计后续“硬件接入预留”的实物验证。当前软件已实现遥测上报接口（模拟数据验证），真实硬件尚未接入。
> 原则：只做只读采集，不做市电控制；先买最小包，跑通再补。
> 价格是 2026 年 11 月电商参考价，按实际下单为准。

## 一、先定演示对象

推荐二选一：

1. **安全演示（推荐先做）**：5V USB 小风扇/小灯 + INA219 电流检测 + SHT30 温湿度 + 门磁 + OLED。
2. **真实设备（有老师在场再做）**：实验楼交换机/AP 的 220V 电源线 + SCT-013 卡扣电流 + SHT30 + 门磁。

## 六、接线规划（ESP32-S3）

| 模块 | 引脚 | 说明 |
|---|---|---|
| SHT30 | 3.3V / GND / SDA / SCL | I2C 地址 0x44/0x45 |
| INA219 | 3.3V / GND / SDA / SCL | I2C 地址 0x40–0x4F |
| ADS1115（交流包） | 3.3V / GND / SDA / SCL | I2C 地址 0x48 |
| OLED | 3.3V / GND / SDA / SCL | I2C 地址 0x3C |
| MC-38 门磁 | GPIO + GND | 内部/外部 10k 上拉，关门/开门电平按实物确认 |
| 水浸（可选） | GPIO + GND | 干接点，低电平触发 |
| 蜂鸣器（可选） | GPIO + GND | 有源蜂鸣器，注意电流 |
| 5V 电源 | 5V / GND | ESP32 DevKit 5V 输入；传感器全部 3.3V |

> I2C 设备多时，SDA/SCL 各加 4.7k–10k 上拉；模块自带上拉时不要重复并太多。

## 七、网络与部署（容易漏）

- ESP32 只支持 **2.4GHz Wi-Fi**，不支持 5GHz；校园网若有 Portal 认证，ESP32 连不上。
- 最稳：手机开 2.4GHz 热点，或用一个便携路由器；电脑和 ESP32 在同一网段。
- 若用 MQTT：笔记本跑 Mosquitto，或树莓派跑；主题 `campus/devices/<asset_code>/telemetry`。
- 若用 HTTP：ESP32 直接 POST 到 `http://<电脑IP>:8100/repair/api/telemetry`。
- 固定 IP / DHCP 保留；给采集盒贴 IP 和 asset_code 标签。
- 时间：ESP32 用 NTP 对时；后端校验时间戳，拒绝未来时间。
- 断网：ESP32 用 LittleFS 缓存最近 N 条，恢复后重发；每条带 `msg_id` 做幂等。
- 供电：采集盒放在有插座的位置；不要从被监测设备内部偷电。

## 八、演示脚本（硬件部分）

1. 扫码 `NET-AP-001` → 资产页显示“在线 / 温度 / 电流”。
2. 打开机柜门 → 门磁触发 → 管理端出现“门磁告警” → 自动生成工单。
3. 关掉 5V 风扇 → INA219 电流变 0 → “设备断电”告警。
4. 用吹风机远距离吹 SHT30（不要贴近）→ 温度超阈值 → 告警。
5. 水浸探头放少量水（可选）→ 漏水告警。
6. 管理端处理工单 → 资产页显示最近工单和遥测曲线。

**工具**：如果没有，另算 ¥150–300。

## 十、不要买

- 220V 继电器板、裸线市电模块、非认证电源。
- 树莓派 5、工控机、PLC：过度。
- 云智能插座/云传感器：依赖厂商云，隐私和离线不可控。
- 433MHz 成品套装：还要额外网关，协议不透明。
- 摄像头/机器人/机械臂：容易跑偏，论文讲不清。
