# 校园报修 · 智能分诊与工单自动化

学生一句话报修 → AI 自动分诊（类别 / 优先级 / 先给自检步骤）→ 生成工单 → 管理员流转处理 → 统计报表。

- 学生端：`/`
- 管理端：`/admin`（`/admin?settings=1` 直接打开 AI 设置）
- 技术栈：Flask + SQLite + 原生 HTML/CSS/JS（零 CDN、零前端框架）
- AI：OpenAI 兼容 / Anthropic 兼容，**无 Key 时自动降级为规则分诊，功能完整可用**

## 双击使用

双击 `校园报修系统.exe`：自动启动内置服务，弹出两个无地址栏应用窗口（学生端 + 工单管理台）。

- 首次运行在 **exe 同目录**自动创建 `tickets.db` 并写入 15 条演示数据
- 每次启动自动把上一份数据库备份为 `tickets.db.bak`
- 日志写入同目录 `desktop.log`（2MB 自动轮转，保留 2 份）
- 关闭两个窗口后约 30 秒自动退出（窗口句柄检测）
- 首次运行 Windows 可能提示“未知发布者”（exe 未签名），点“仍要运行”
- 依赖系统已安装 Edge（Windows 10/11 自带）

**数据管理**：管理端「⚙ AI 设置」→ 底部「数据与日志」可查看数据库路径/大小/数量、下载备份、一键重置演示数据。

## 开启 AI 分诊（两种方式）

**方式一（推荐）：软件内设置**

管理端右上角「⚙ AI 设置」→ 选预设或手动填写 → 「测试连接」→ 「保存」，立即生效。

- **API 格式**：OpenAI 兼容（DeepSeek / Kimi / 硅基流动 / 智谱等）或 Anthropic 兼容（Claude）
- **Base URL、模型名、API Key**：均可自定义；Key 只保存不回显（界面显示打码值）
- 「清除 Key」可随时退回规则分诊

**方式二：配置文件**

`config.example.json` 复制为 `config.json`（桌面版放 exe 同目录），填写后重启：

```json
{
  "api_key": "sk-xxxx",
  "api_format": "openai",
  "model": "deepseek-flash",
  "base_url": "https://api.deepseek.com",
  "port": 8000,
  "timeout": 8
}
```

成本参考：每次分诊几百 token，充 10 元可用很久。

## 统计口径（元审计要求：口径必须可审计）

| 指标 | 定义 |
|---|---|
| 今日新增 | `created_at` 落在服务器本地日期（YYYY-MM-DD）内的工单数 |
| 待处理 / 处理中 | `status ∈ {pending, processing}` 的工单数 |
| 平均处理时长 | 已完成/已关闭工单的 `(done_at - created_at)`，单位小时；无完成时间的不计入 |
| 近 7 天分类分布 | `created_at` 日期 ≥（今天 − 7 天，含第 7 天当天）的工单按类别计数 |
| 累计 AI 用量 | 所有工单 `total_tokens` 之和；演示数据的消耗记为 0（不虚构模型消耗） |
| 状态机 | 允许任意状态间人工流转（含已关闭重开），每次流转写入 `events` 留痕 |
| 工单号 | `BX + 创建日期 + 当日 3 位序号`；并发写入加锁，保证唯一 |

## 分诊机制（可靠性设计）

1. **知识库注入**：关键词命中 23 个故障场景（来源：网络排障助手知识库，导出为 `kb_snippet.json`），把“快速判断 + 步骤”作为参考材料注入提示词（朴素 RAG）。
2. **结构化输出**：要求 LLM 只输出 JSON（类别/优先级枚举、checks、confidence），服务端做 schema 校验。
3. **重试与降级**：校验失败重试 1 次；超时（8s）、空输出、非法类别 → 自动降级为关键词规则分诊，界面标注“规则分诊”。
4. **低置信转人工**：置信度 < 0.75 在管理端标记“待确认”，管理员可一键改类别（留痕到处理记录）。
5. **防提示词注入**：输入限 500 字、用户原文包裹在固定标签内、system 提示只允许 JSON。
6. **重复报修检测**：同地点 + 同类别存在未关闭工单时提示“已有处理中工单”，确认后可强制提交。

## 源码运行（开发）

```bash
cd src
pip install flask openai requests
python seed.py          # 生成演示数据（重置：python seed.py --reset）
python app.py           # http://127.0.0.1:8000/
```

手机访问：手机与电脑同一 WiFi，访问 `http://<电脑局域网IP>:8000/`（启动监听 `0.0.0.0`）。

桌面版调试：`python src/desktop.py`（数据写入 `src/data/`）。

## 构建 exe

双击 `构建/build.bat`，或执行：

```bash
python 构建/build.py
```

产物输出到根目录 `校园报修系统.exe`，中间文件收在 `构建/` 内。

## 自测

```bash
cd src
python qa_api.py
```

启动独立实例（临时库 + 临时配置 + 8765 端口，不碰演示数据），覆盖：AI 输出解析与校验、四类分诊准确性、高优先级识别、重复报修、强制提交、状态流转、人工改类别留痕、统计、过滤、边界（空/超长/404/非法状态）、AI 设置读写与 Key 打码、页面可访问。全绿退出码 0。
